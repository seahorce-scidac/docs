Uses midpoint method to advance particles using flow velocity.

Midpoint-method advection in terrain-following coordinates. Horizontally the particle moves with u and v at a fixed fractional w-level index (see REMORA_PC.H), so it follows the s-levels over sloping bathymetry; vertically it moves across the levels at omega / Hz. The index is reflected off the bed and the free surface and then mapped back to a height, so a particle can never leave the water column.

Particle positions are in the uniform coordinates of the AMReX geometry, whose cell size is (prob_hi - prob_lo) / n_cell, while u and v are physical velocities along the grid directions. They are converted with the local metric, dx/dt = u * pm * dx_geom and dy/dt = v * pn * dy_geom, so particles cover the right physical distance on stretched or curvilinear grids; on a uniform grid the factors are 1.

The index s is stored with the particle and advanced directly; the height is then set from it on the current grid. As the free surface moves between steps, the particle therefore moves with the levels. Both stages of the midpoint method run in one kernel; nothing between them needs the particles redistributed, since the midpoint stays within the ghost cells of the particle's grid.

Compute mass density, per unit of physical cell volume Hz/(pm*pn)

Mass per unit physical volume, by cloud-in-cell deposit in index space. Horizontally the weights come from the particle's position in the uniform coordinates it moves in, and vertically from its level index s (cell k spans s in [k, k+1]), so the deposit lands in the cells around the particle whatever the stretching of the levels. Weight that would fall below the bed, above the free surface or across a non-periodic side of the domain goes to the edge cell instead, so no mass is lost. The deposited mass is then divided by each cell's volume, Hz/(pm*pn).

Read the particles from a checkpoint. A checkpoint written before the level index was stored is read too: s is then computed from each particle's height on a_z_phys_nd, the grid the checkpoint holds.

Checkpoints written before the level index s was stored have one real component fewer. Such a checkpoint is read into a container with that layout, the particles are copied into this one, and s is computed from each particle's height on a_z_phys_nd, the grid read from the same checkpoint. That is the index the particle's next step would have recovered.

void REMORAPC::WriteOutput ( const std::string & a_fname,
const std::string & a_name,
const amrex::Vector< amrex::MultiFab > * a_xy = nullptr )

Write the particles for a checkpoint, or with a_xy for a plotfile with x and y in physical coordinates

Write the particles of one species, for a checkpoint or a plotfile. With a_xy null they are written as they are, in the uniform coordinates of the AMReX geometry they move in. With a_xy given (plotfiles), x and y are replaced by the physical coordinates of the cell corners (psi points) interpolated bilinearly to each particle. These are the corner positions the plotfile's nodal displacement gives a viewer, so each particle is drawn inside the cell that holds it. z is already the physical height. The uniform x and y are saved before the conversion and restored bit for bit after the write, so writing a plotfile does not change the run.

Each particle stays filed under the grid that physically holds it, though its physical position need not map to that grid through the uniform geometry, so pc.OK() does not hold during the write. AMReX's particle writers do not require it (AMReX-Codes/amrex#6175).

Parameters
a_fnamecheckpoint or plotfile directory
a_nameparticle species name
a_xynull, or per level the physical x and y of the psi points (REMORA::plot_node_coords)
