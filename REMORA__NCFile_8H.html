Read the part of each variable that this rank needs, collectively.

Reads the same data as BuildFABsFromNetCDFFile, in the same index space, but each rank reads, and holds, only the file data inside the boxes of region (converted to each variable's staggering): one FAB per box, in an NCLocalFab. NCLocalFab::copy_to into a MultiFab FAB this rank owns gives the same values as a copy from BuildFABsFromNetCDFFile's FAB, when region came from nc_local_region for that MultiFab.

Collective over amrex::ParallelContext::CommunicatorSub(): every rank calls it, including ranks with an empty region. Each variable is one collective read per box; ranks with fewer boxes than the most any rank has make empty reads to match, as a collective read needs. That works for every format PnetCDF opens, compressed NetCDF-4 included. River data, which is not laid out on the model grid, is not supported here.

◆ nc_local_region() [2/3]

NCRegion nc_local_region ( const amrex::Vector< const amrex::MultiFab * > & mfs)
inline

The boxes, cell-centered and with ghost cells, of every FAB this rank owns in each of mfs: the region BuildLocalFABsFromNetCDFFile has to read for a copy into them. Empty on a rank that owns none. Null entries are skipped.

Boxes are merged while their bounding box holds no more cells than the two do together, so the same box in several MultiFabs, or a FAB and the neighbor whose ghost cells it overlaps, become one read; FABs far apart stay separate reads, so a rank never reads the space between them. With remora.v >= 1 the result is printed: the largest ratio over the ranks of cells to be read to cells owned.

Collective over amrex::ParallelContext::CommunicatorSub() when remora.v >= 1.

double ReadNetCDFTimeOffsetDays ( const std::string & fname,
const std::string & time_name,
double time_ref,
bool units_required,
bool announce )

Offset, in days, that puts a file's time variable onto the model clock.

Reads the units attribute of time_name, which must count days, and its calendar attribute if it has one. A days since <date> reference date is converted to days since the date remora.time_ref names, so a file whose epoch differs from the run's is still read at the right time; the offset is zero when the two dates agree. A time variable with no reference date is taken to be on the model clock already. A calendar that disagrees with time_ref is an error, since the two would count days differently.

Collective: the attributes are read on the I/O processor and the result is broadcast. The mapping applied is printed, so a reader of the log can see it.

Parameters
[in]fnameNetCDF file
[in]time_namename of the time variable
[in]time_refremora.time_ref
[in]units_requiredabort when the time variable has no units attribute; otherwise warn and assume days on the model clock
[in]announceprint the mapping; false for a series that is set up but will never be read
