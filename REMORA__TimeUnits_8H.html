Detailed Description

The CF units attribute of a NetCDF time variable, and how it maps onto the model clock.

A forcing, boundary, river or climatology file stamps its records with a time variable whose units read days since <date>, or just days. The model clock counts from the date remora.time_ref names (see REMORA_DateClock.H), so a file time is on the model clock only after the difference between the two reference dates is added: 

model days = file days + (datenum(file reference) - datenum(time_ref))

remora_time_units_offset_days computes that bracket, in the calendar time_ref selects. It is zero when the file counts from the same date as the run, which is the usual case, and a file with no reference date is taken to be on the model clock already.

remora_parse_time_units reads the attribute. It accepts the CF form, <unit> since YYYY-MM-DD[ hh:mm[:ss[.s]]][ UTC|Z|+00:00], and it skips words between since and the date, so days since initialization, 2020-01-01 00:00:00 reads as 2020-01-01. It does not interpret a time zone other than UTC. Host only: it works on std::string.

Whether a CF calendar attribute names the calendar time_ref selects.

360_day goes with time_ref = -1 and nothing else. Every other time_ref is Gregorian: gregorian, standard and proleptic_gregorian all agree for dates after 1582, which is where the model clock lives. julian, noleap and the rest count days differently and are rejected.

Days to add to a time counted from units' reference date to count it from the date time_ref names instead.

Zero for a file with no reference date, which is taken to be on the model clock already, and zero when the two dates agree. The day numbers are both taken in the calendar time_ref selects, as remora_caldate does.
